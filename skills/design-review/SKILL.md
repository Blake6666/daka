# Skill：前端设计规则约束与验证（design-review）

> 用途：在任何前端页面/组件 **改动之前** 做约束、**改动之后** 做验证的一套可重复流程。
> 来源：daka 项目 Day 7~11 实测沉淀（对比度 22 处不达标、手机首屏 0 条内容、可点区 15×13px
> 等问题都是这套方法量出来并修掉的）。规则不绑死具体业务，换成任何数据对象都能用。

## 调用方法

对 AI 说：**「按 `skills/design-review/SKILL.md` 约束本次改动」**，然后描述要做什么。
AI 必须先走【修改前检查】再动手，改完必须走【修改后验证】并把结果数字报出来。

---

## 一、六类规则（改动时必须遵守）

### 1. 页面层级
- 一屏之内要能看到"核心内容"（首屏至少露出 3~5 条核心数据/条目，不许被头部区域占满）
- 视觉权重排序：核心数据 > 操作入口 > 说明文字 > 装饰。装饰不许压过内容
- 同类信息用同一个组件渲染，不许一处一个样式

### 2. 颜色与字体
- 所有颜色收进一张 token 表（在 `:root` 里定义 CSS 变量），新增颜色必须能在表里找到出处
- 文字对比度（WCAG）：正文 ≥ **4.5:1**，大字（≥24px 或 ≥19px 加粗）≥ **3:1**
- **彩色底上不放浅色小字**；渐变背景/渐变文字要按"最浅色标 vs 字色"算对比度
- 字号收敛到 8 档以内，不用 12.5/13.5 这类肉眼分不出的"半档"
- 深色模式不是简单反色：彩色文字/边框要分档压深或提亮，逐项核对

### 3. 卡片与按钮
- 按钮五态齐全：默认 / 悬停 / 激活 / 禁用 / **键盘焦点（`focus-visible` 必须可见，禁止裸 `outline: none`）**
- 可点区域：鼠标端 ≥ **32×32px**，触屏端 ≥ **40×40px**；撑大可点区用不参与布局的方式
  （绝对定位透明层），不许把布局顶变形
- 交互必须有反馈：操作前—处理中—成功—失败四态，处理中禁止重复提交
- 卡片间距用 4 的倍数（4/8/12/16/24），悬停阴影变化过渡 ≤ 0.2s

### 4. 移动端适配
- 断点 ≤560px（手机）/ ≤900px（平板），每档实测
- 任何宽度下**横向溢出 = 0px**
- 多个横排控件放不下时优先"单行横向滚动"（左侧标签 sticky），其次两列，避免无限换行堆高
- 触屏没有 hover：靠悬停出现的按钮在触屏端要常显

### 5. 可访问性（余力加练项）
- 所有图标按钮有 `aria-label`；纯装饰元素加 `aria-hidden="true"`
- 键盘走 Tab 能到达每个交互控件，焦点环可见
- 动效尊重 `prefers-reduced-motion`

## 二、修改前检查（动手前，5 分钟）

1. **定位**：说清楚要改的文件和选择器，先 `grep` 确认目标样式真实存在（避免选择器写空）
2. **范围声明**：只改哪些文件/哪一段，明确"不许动"的清单（数据、接口、无关组件）
3. **回归底线**：改之前跑一次现有功能的回归测试，记录全绿基线（改完对比）
4. **同文件多处改动必须串行**，并行编辑会互相覆盖

## 三、修改后验证（必须量出数字，不接受"看起来好了"）

| 检查项 | 方法 | 合格线 |
|---|---|---|
| 构建 | `vite build` | 0 error |
| 运行时崩溃 | 无头浏览器打开页面 + 监听 console | 0 报错 |
| 横向溢出 | `document.documentElement.scrollWidth ≤ clientWidth` | 桌面 1440 + 手机 360/390 双测 |
| 对比度 | getComputedStyle 取字色/底色代入 WCAG 公式（渐变取最差色标） | 正文 ≥4.5，大字 ≥3 |
| 可点尺寸 | getBoundingClientRect + `elementFromPoint` 命中测试 | ≥32（鼠标）/ ≥40（触屏） |
| 老功能回归 | 跑改动前的同一套回归脚本 | 与基线一致全绿 |

---

## 四、3 个成功标准（可观察）

1. **改动范围内每个新颜色值都能在颜色 token 表里找到出处**（grep 可查，找不到 = 违规）
2. **验证表六项全部量出数字且达标**，不是"目测没问题"
3. **老功能回归与改动前基线一致**，桌面端表现零变化（除非本次任务就是改桌面端）

## 五、教训清单（前人踩过的坑，别再踩）

- 只看 HTTP 200 不算验证——必须查运行时崩溃（白屏教训）
- 肉眼看低分辨率截图会误判 DOM——判对错一律查 DOM/getComputedStyle
- 测量脚本本身会有 bug（如不识别渐变背景导致 163 处假报）——**报数字前先验证尺子**
- 测异步状态要卡准时间窗（等早了读不到、等晚了已消失）
- 用尺寸撑大可点区会顶坏布局——用不参与布局的透明层
